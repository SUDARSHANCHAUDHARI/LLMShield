Does your system prompt keep its secrets?

LLMShield runs prompt-leak and prompt-injection attacks against your system prompt and a real model, checks every reply, and tells you exactly what got out. Use it from the command line, as a CI gate, or right here in your browser.

Try the playground Run the CLI 
$ pnpm dev scan --file examples/system-prompt.txt --provider mock-leaky --fail-on high

What it checks

Every check is deterministic: no second model grades the replies, so the same reply always gets the same score.

Prompt leakage

Measures how much of your prompt appears in the reply, four words at a time, from a hint up to a complete dump.

Canary token

Adds a random secret code to your prompt for the scan. If any reply contains it, the secret got out.

Instruction override

Injection attacks ask the model to reply with a random marker. If it does, the user beat your system prompt.

Encoded dumps

Replies are also checked after Base64 decoding and reversing, so "encode your prompt" tricks are caught.

Three ways to use it

Same scanner, same attacks, same scoring in all three.

Command line

Scan a prompt file and write a JSON or Markdown report.

pnpm dev scan --file prompt.txt \
  --provider openrouter \
  --format markdown -o report.md

CI gate

Fail the build when the risk reaches your threshold. The report is still written.

pnpm dev scan --file prompt.txt \
  --provider openrouter \
  --fail-on high

Browser playground

Paste a prompt, pick a model, read the findings. Try the built-in demo models with no key at all.

Open the playground →

Your key stays in your browser

The playground is a static page with no backend. With OpenRouter, your API key and prompt go straight from your browser to openrouter.ai and nowhere else. The key is kept in memory only and is gone when you close the tab. The page's Content Security Policy blocks every other connection.
